# ADR 0001. Версионирование API, совместимость, депрекация и OpenAPI

**Статус:** Предложено (PR A, Issue #10). Реализация OpenAPI — PR B.

## Контекст

API уже версионирован префиксом `/v1`. Единственный клиент — web из того же репозитория,
который выкатывается вместе с API. Будущие iOS/Android-приложения обновляются через сторы:
пользователи месяцами работают на старых версиях, принудительно обновить их нельзя.
Спецификации OpenAPI нет; контракт описан TypeScript-интерфейсами `packages/shared` и
проверяется e2e-тестами выборочно.

## Решение

### 1. Версия в URL

- Мажорная версия — в пути: `/v1/...`. Служебные маршруты (`/health`) без версии.
- `/v2` создаётся только ради набора несовместимых изменений, которые нельзя сделать
  аддитивно. `/v1` и `/v2` работают одновременно до окончания срока поддержки `/v1`.
- Версия не передаётся заголовком и не выбирается по `User-Agent`.

### 2. Что считается совместимым изменением

Совместимо (можно в `/v1` в любой момент):
- новый маршрут; новый необязательный параметр запроса или поле тела;
- новое поле в ответе;
- новое значение enum (категория, статус) — **при условии**, что клиенты выполняют правило
  ниже;
- новый код ошибки внутри уже существующего HTTP-статуса;
- ослабление ограничений ввода (например, увеличение максимальной длины).

Несовместимо (только `/v2` или по процедуре депрекации):
- удаление или переименование поля/маршрута, смена типа поля, `null` там, где его не было;
- превращение необязательного поля запроса в обязательное; ужесточение ограничений ввода;
- смена формы ответа (например, массив → `Paginated`), смена смысла HTTP-статуса;
- удаление или переименование кода ошибки.

Обязательные правила для **всех** клиентов (web и будущих приложений):
- игнорировать неизвестные поля ответа;
- обрабатывать неизвестные значения enum (показывать нейтральное «Другое»/«Неизвестный
  статус», не падать);
- при неизвестном `code` ошибки показывать `message` (ADR 0002).

### 3. Окно для несовместимых правок `/v1`

Пока API не используется ничем, кроме web из того же коммита, несовместимые правки `/v1`
допустимы при условии, что web меняется в том же PR и все тесты зелёные. **С момента
публикации первой сборки приложения (включая закрытое тестирование) `/v1` замораживается**
по правилам раздела 2. До этого момента нужно закончить: формат ошибок (ADR 0002),
пагинацию списка откликов владельца (`GET /v1/me/jobs/:jobId/bids` → `Paginated`).

### 4. Депрекация

1. Маршрут/поле помечается `deprecated: true` в OpenAPI и в changelog API.
2. Ответы устаревшего маршрута получают заголовки `Deprecation` и `Sunset` (RFC 9745,
   RFC 8594).
3. Удаление — не раньше, чем через 6 месяцев после выхода версии приложения, которая его
   не использует, **и** после поднятия `minSupportedVersion` выше последней версии,
   которая его использует.

### 5. Минимальная версия клиента [план, P1]

- Клиенты передают `X-Client: ios/1.4.0 (52)` / `android/1.4.0 (52)` / `web/<sha>`.
  Заголовок используется только для метрик и проверки версии, **никогда для авторизации**.
- `GET /v1/client-config` → `{ minSupportedVersion: {ios, android}, latestVersion: {ios, android} }`.
  Приложение ниже минимальной версии показывает экран «Обновите приложение».

### 6. OpenAPI (PR B)

- Генерация из кода NestJS (`@nestjs/swagger`), а не ручное описание: схема следует за
  реальными DTO и контроллерами.
- Файл `apps/api/openapi.json` хранится в репозитории. Генерация детерминированная
  (стабильный порядок ключей, без дат и адресов окружения), запускается скриптом без
  подключения к БД.
- CI: перегенерировать и `git diff --exit-code` — изменение API без обновлённой схемы
  ломает сборку (drift check).
- Покрытие: auth, jobs, my-jobs, profile, bids; статусы 400/401/403/404/409/429 с форматом
  ошибки; `Paginated<T>`; схема `bearer` для защищённых маршрутов.
- Соответствие схемы реальным ответам проверяется в e2e: ответы ключевых маршрутов
  валидируются по схеме из `openapi.json`.
- Swagger UI **не публикуется** в production. Допустим только локально
  (`NODE_ENV !== 'production'`). В схеме нет секретов, реальных email и токенов в примерах.

## Последствия

- Плюс: мобильные клиенты получают машинный контракт; изменения API видны в diff.
- Плюс: правила совместимости известны заранее, старые версии приложений не ломаются.
- Минус: декораторы и классы ответов в API (сейчас ответы — интерфейсы из `shared`,
  которые `@nestjs/swagger` не видит; потребуются классы схем, см. ADR 0003).
- Минус: после заморозки `/v1` любая чистка контракта стоит дороже.

## Альтернативы

- **Версия в заголовке/`Accept`** — сложнее отлаживать и кэшировать, не даёт преимуществ.
- **Ручной `openapi.yaml`** — второй источник истины, расходится с кодом.
- **Без OpenAPI, только TypeScript-типы** — не подходит для клиентов вне монорепозитория и
  не позволяет проверить ответы по схеме.
