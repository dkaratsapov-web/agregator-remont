# ADR 0001. Версионирование API, совместимость, депрекация и OpenAPI

**Статус:** Предложено (PR A, Issue #10), редакция 2 — после аудита PR #11.
Реализация OpenAPI — PR B.

## Контекст

API уже версионирован префиксом `/v1`. Единственный клиент — web из того же репозитория,
который выкатывается вместе с API. Будущие iOS/Android-приложения обновляются через сторы:
пользователи месяцами работают на старых версиях, принудительно обновить их нельзя, и
старая сборка могла быть выпущена с ошибками обработки ответа. Спецификации OpenAPI нет.

## Решение

### 1. Версия в URL

- Мажорная версия — в пути: `/v1/...`. Служебные маршруты (`/health`) без версии.
- `/v2` создаётся только ради набора несовместимых изменений, которые нельзя сделать
  аддитивно. `/v1` и `/v2` работают одновременно до окончания поддержки `/v1` (раздел 5).
- Версия не передаётся заголовком и не выбирается по `User-Agent`.

### 2. Открытые и закрытые enum'ы

Каждый enum в OpenAPI помечается явно:
- **открытый** (`x-extensible-enum`): список может расширяться, клиент обязан показывать
  неизвестное значение нейтрально. Кандидаты: `JobCategory`, коды ошибок.
- **закрытый**: значения определяют логику клиента. `JobStatus`, `BidStatus`, `UserRole`,
  будущие статусы сделки (FSM). Новое значение закрытого enum в ответе — **несовместимое**
  изменение.

Пометка делается до первой мобильной сборки; первая сборка обязана реализовать запасной
вариант для всех открытых enum'ов и неизвестных кодов ошибок (раздел 6, контрактные тесты
клиента).

### 3. Матрица совместимости

| Изменение | В запросе | В ответе |
| --- | --- | --- |
| Новый маршрут | совместимо | совместимо |
| Новое необязательное поле / параметр | совместимо | совместимо (клиенты игнорируют неизвестные поля) |
| Новое обязательное поле | **несовместимо** | совместимо |
| Удаление / переименование поля | совместимо, если сервер его больше не требует | **несовместимо** |
| Смена типа или формата поля, `null` где его не было | **несовместимо** | **несовместимо** |
| Новое значение открытого enum | совместимо | совместимо |
| Новое значение закрытого enum (статус FSM, роль) | совместимо, если старые клиенты его не отправляют | **несовместимо**: только новое поле, `/v2` или выдача лишь клиентам с версией ≥ N (раздел 5) |
| Ослабление ограничения ввода (больше длина) | совместимо | — |
| Ужесточение ограничения ввода | **несовместимо** | — |
| Новый код ошибки в уже возможном HTTP-статусе | — | совместимо при наличии запасного варианта в клиенте (ADR 0002) |
| Новый HTTP-статус для существующего маршрута | — | **несовместимо** |
| Смена формы ответа (массив → `Paginated`) | — | **несовместимо** |
| Смена смысла статуса / кода | — | **несовместимо** |

### 4. Окно для несовместимых правок `/v1`

Пока API не используется ничем, кроме web из того же коммита, несовместимые правки `/v1`
допустимы при условии, что web меняется в том же PR и все тесты зелёные. **С момента
публикации первой сборки приложения (включая закрытое тестирование) `/v1` замораживается**
по матрице выше. До этого момента нужно закончить: формат ошибок (ADR 0002), пагинацию
списка откликов владельца, разметку открытых/закрытых enum'ов.

### 5. Депрекация, поддержка старых версий и вывод из обращения

1. Маршрут/поле помечается `deprecated: true` в OpenAPI и в changelog API; ответы получают
   заголовки `Deprecation` и `Sunset` (RFC 9745, RFC 8594).
2. **Телеметрия версий**: клиенты передают `X-Client: ios/1.4.0 (52)`, `android/1.4.0 (52)`,
   `web/<sha>`. Сервер считает агрегированные счётчики запросов по версии клиента и маршруту,
   без идентификаторов пользователей и IP.
3. Удаление — когда выполнены **оба** условия: прошло не меньше 6 месяцев после выхода
   версии, которая не использует устаревшее; **и** по телеметрии доля запросов от версий,
   которые его используют, ниже порога (предложение: < 1% за последние 30 дней). Календарь
   без телеметрии основанием не является.
4. Пользователи неподдерживаемых версий: `GET /v1/client-config` → `{ minSupportedVersion,
   latestVersion }` по платформам; приложение ниже минимальной версии показывает экран
   «Обновите приложение». Сервер дополнительно может отвечать `426`/`CLIENT_UPGRADE_REQUIRED`
   на маршрутах, где старый клиент сломался бы.
5. Выдача нового значения закрытого enum только клиентам с версией ≥ N по `X-Client`
   допустима как мера **совместимости**.

**`X-Client` и `minSupportedVersion` — не механизмы безопасности.** Заголовок подделывается,
проверку версии на клиенте можно обойти. Ни одна проверка доступа, лимит или исправление
уязвимости не опирается на версию клиента: защита всегда на сервере и действует для всех
версий одинаково.

### 6. OpenAPI и проверка контракта (PR B)

- Генерация из кода NestJS (`@nestjs/swagger`), а не ручное описание.
- Файл `apps/api/openapi.json` хранится в репозитории. Генерация детерминированная
  (стабильный порядок ключей, без дат и адресов окружения), запускается скриптом без
  подключения к БД.
- CI, проверка 1 (drift): перегенерировать и `git diff --exit-code`.
- CI, проверка 2 (обратная совместимость): текущая схема сравнивается со снимками схем
  выпущенных версий приложений (`docs/api-snapshots/<платформа>-<версия>.json`) утилитой
  поиска несовместимых изменений OpenAPI (например, `oasdiff breaking`). Несовместимое
  изменение без `/v2` ломает сборку. До первой мобильной сборки снимков нет, проверка 2
  пустая.
- CI, проверка 3 (схема = реальные ответы): e2e-тесты валидируют ответы и ошибки ключевых
  маршрутов по `openapi.json` (подробно — ADR 0003).
- Покрытие: auth, jobs, my-jobs, profile, bids; статусы 400/401/403/404/409/429 с форматом
  ошибки; `Paginated<T>`; схема `bearer` для защищённых маршрутов.
- Контрактные тесты клиентов (когда появится приложение): клиент разбирает ответы с
  неизвестными полями, неизвестными значениями открытых enum'ов и неизвестными кодами
  ошибок без падения.
- Swagger UI **не публикуется** в production. Допустим только локально
  (`NODE_ENV !== 'production'`). В схеме нет секретов, реальных email и токенов в примерах.

## Последствия

- Плюс: мобильные клиенты получают машинный контракт; несовместимые изменения ловит CI.
- Плюс: правила совместимости и вывода из обращения известны заранее.
- Минус: в API появляются декораторы и классы схем ответов (ADR 0003).
- Минус: после заморозки `/v1` любая чистка контракта стоит дороже; поддержка нескольких
  версий требует телеметрии.

## Альтернативы

- **Версия в заголовке/`Accept`** — сложнее отлаживать и кэшировать, не даёт преимуществ.
- **Ручной `openapi.yaml`** — второй источник истины, расходится с кодом.
- **Без OpenAPI, только TypeScript-типы** — не подходит для клиентов вне монорепозитория и
  не позволяет проверить ответы по схеме.
- **Фиксированный срок поддержки без телеметрии** — не гарантирует, что старые клиенты
  исчезли.
