# ADR 0004. Роль Next.js как BFF, граница web/mobile, deeplink'и

**Статус:** Принято владельцем (Issue #10). Фиксирует текущую практику; runtime не меняется.

## Контекст

Web (Next.js App Router) читает данные в RSC и меняет их через Server Actions. Все
бизнес-правила проверяет API (`docs/MOBILE_READINESS_AUDIT.md`, раздел 3). У web нет
доступа к БД (`DATABASE_URL` в контейнер web не передаётся). Будущие приложения должны
работать с теми же правилами, не проходя через web.

## Решение

### Server Actions и RSC — только адаптер

Разрешено в web:
- разбор формы и UX-валидация (понятные ошибки до запроса);
- вызов API с токеном из cookie и IP посетителя;
- перевод ответа/ошибки API в интерфейс, редиректы;
- защита браузерной сессии: проверка `Origin` (`WEB_PUBLIC_ORIGIN`), cookie
  `__Host-ar_session`, безопасный редирект.

Запрещено в web:
- решать «можно ли» (владение, роль, статус, квоты) — только API;
- прямой доступ к БД, Prisma, секретам API;
- вычислять данные, которые затем считаются доверенными API;
- быть публичным API для других клиентов: мобильное приложение ходит в NestJS напрямую,
  Server Actions не являются стабильным контрактом.

Проверка правила в ревью: если функцию нельзя выполнить через `/v1` без web — в API чего-то
не хватает.

### `apps/mobile`

Папка и шаблон не создаются до решения владельца о запуске мобильной разработки
(ТЗ рекомендует React Native + Expo). Удобный мобильный сайт/PWA остаётся приоритетом.

### Deeplink'и

- Ссылки — обычные `https`-адреса сайта, одинаковые для web и приложений
  (Universal Links на iOS, App Links на Android). Своя схема `agregator://` — только
  запасной вариант, не для входа и не для передачи токенов.
- Namespace (совпадает с маршрутами web, новые — по тому же принципу):

  | Ссылка | Что открывает | Доступ |
  | --- | --- | --- |
  | `/jobs/:id` | публичная карточка заказа | всем |
  | `/account/jobs/:id` | свой заказ и отклики на него | владелец |
  | `/account/bids` | мои отклики | подрядчик |
  | `/account/chats/:id` [план] | диалог | участник |
  | `/account/deals/:id` [план] | сделка | участник |

- Ссылка только открывает экран. Никаких действий по открытию (выбор исполнителя,
  отзыв отклика) и никаких токенов/секретов в URL.
- Приложение после открытия ссылки запрашивает данные через API со своей сессией; если
  входа нет — вход и возврат на тот же путь; если API вернул 404 — «не найдено» (чужой
  ресурс неотличим от несуществующего).
- Файлы `/.well-known/apple-app-site-association` и `/.well-known/assetlinks.json`
  публикует web, когда появятся идентификаторы приложений [план, P1].

## Последствия

- Web и приложения равноправные клиенты одного API; правила не дублируются.
- Новые функции сначала появляются в API с тестами доступа, затем в клиентах.

## Альтернативы

- **Приложение через BFF (Server Actions или route handlers web)** — превращает web в
  публичный API без контракта, смешивает CSRF-защиту cookie с токенами устройств.
- **Отдельный BFF для mobile** — не нужен, пока API не содержит web-специфики.
