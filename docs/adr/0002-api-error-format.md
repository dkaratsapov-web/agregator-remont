# ADR 0002. Единый формат ошибок API с машинным `code`

**Статус:** Предложено (PR A, Issue #10). Реализация — PR C.

## Контекст

Сейчас ошибки — стандартный формат NestJS `{ statusCode, message, error }`. `message` —
русская строка, для ошибок валидации — массив строк. Машинного кода нет: пять разных 409
(email занят, заказ не открыт, отклик уже есть, отклик не на рассмотрении, заказ закрыт) и
два разных 429 (лимит частоты и суточная квота) различимы только по тексту. Web показывает
`message` (или первый элемент массива), поэтому сейчас работает; мобильному клиенту нужно
различать ситуации без разбора текста (повторить через минуту или нет, какое поле
подсветить).

## Решение

Формат v1 — **аддитивное** расширение текущего, без удаления полей:

```json
{
  "statusCode": 409,
  "code": "JOB_NOT_OPEN",
  "message": "Редактировать можно только открытый заказ",
  "error": "Conflict"
}
```

Для ошибок валидации дополнительно `fieldErrors`:

```json
{
  "statusCode": 400,
  "code": "VALIDATION_FAILED",
  "message": ["Название: от 5 до 160 символов"],
  "error": "Bad Request",
  "fieldErrors": [{ "field": "title", "message": "Название: от 5 до 160 символов" }]
}
```

- `code` — всегда; стабильная строка `UPPER_SNAKE_CASE`; клиенты ветвятся только по нему.
- `message` — текст для показа пользователю; форма поля в v1 не меняется (строка или массив
  у валидации), чтобы не сломать текущий web.
- `fieldErrors[].field` — путь к полю в теле/запросе (`title`, `categories.0`).
- 429 сохраняет заголовок `Retry-After` для лимита частоты.

Начальный каталог кодов (точные имена фиксируются в PR C и в OpenAPI):

| HTTP | `code` | Когда |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | DTO/query не прошли проверку |
| 400 | `NO_FIELDS_TO_UPDATE` | пустой PATCH |
| 400 | `BUDGET_RANGE_INVALID` | `budgetMin > budgetMax` |
| 401 | `UNAUTHENTICATED` | нет или недействительная сессия |
| 401 | `INVALID_CREDENTIALS` | неверный email или пароль (одинаково для обоих случаев) |
| 403 | `FORBIDDEN_ROLE` | роль не допускает операцию |
| 404 | `NOT_FOUND` | ресурса нет **или он чужой** — один код, чтобы не раскрывать существование |
| 409 | `EMAIL_TAKEN` | регистрация на занятый email |
| 409 | `JOB_NOT_OPEN` | правка/отклик/выбор исполнителя для неоткрытого заказа |
| 409 | `JOB_ALREADY_CLOSED` | повторное закрытие |
| 409 | `BID_ALREADY_EXISTS` | второй отклик на заказ |
| 409 | `BID_NOT_PENDING` | отзыв или выбор отклика не в статусе «на рассмотрении» |
| 429 | `RATE_LIMITED` | лимит частоты, есть `Retry-After` |
| 429 | `DAILY_QUOTA_EXCEEDED` | суточная квота заказов/откликов |
| 500 | `INTERNAL` | всё непредвиденное; текст общий, без деталей |

Реализация (PR C): глобальный exception filter + класс доменной ошибки с `code`;
существующие `throw new ConflictException(...)` заменяются на доменные ошибки с тем же
статусом и текстом. Ошибки Prisma и прочие неизвестные исключения превращаются в
`INTERNAL` без стека, SQL, email и токенов; подробности — только в серверный лог без ПДн.
Web переходит на `code` с fallback на `message`. Тесты: каждый код хотя бы одним e2e;
неизвестная ошибка → 500 без деталей.

## Последствия

- Совместимо для текущего web (поля не удаляются); мобильные клиенты получают стабильные коды.
- Новый код внутри существующего статуса — совместимое изменение (ADR 0001).
- Тексты остаются русскими; при локализации приложения клиент может переводить по `code`.

## Альтернативы

- **RFC 9457 `application/problem+json`** (`type`, `title`, `detail`) — стандартнее, но
  меняет форму ответа и ломает текущий web; можно принять в `/v2`.
- **Только `message` без кода** — текущее состояние, не подходит для native.
