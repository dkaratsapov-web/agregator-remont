# Агент проверки: безопасность и правильность

Файл агента — `.claude/agents/garantych-reviewer.md`. Это субагент Claude Code: независимый
ревьюер, который знает правила этого проекта (доступ и IDOR, гонки и блокировки строк,
персональные данные и 152-ФЗ, формат ошибок, контракт OpenAPI, совместимость миграций с откатом,
Server Actions, CSP, автодеплой) и проверяет изменение по ним. Код он не меняет: только читает и
запускает проверки (lint, typecheck, тесты, `migration_check.py`, `pnpm audit`).

## Как запустить

- **В Claude Code** (в каталоге репозитория): «Проверь PR #66 агентом garantych-reviewer» или
  «garantych-reviewer: проверь мои незакоммиченные изменения». Агент подхватывается при запуске
  сессии; список — команда `/agents`.
- **Из командной строки**:
  `claude --agent garantych-reviewer -p "Проверь изменения ветки против origin/main"`.

Без указания объёма агент берёт разницу текущей ветки с `origin/main` или незакоммиченные
изменения.

## Что он отвечает

Один отчёт: итог («БЛОКИРУЕТ» / «ЕСТЬ ЗАМЕЧАНИЯ» / «ЗАМЕЧАНИЙ НЕТ»), находки от самой серьёзной
с `файл:строка`, путём воспроизведения, доказательством и статусом (ПОДТВЕРЖДЕНО или ВЕРОЯТНО),
минимальным исправлением и тестом, который должен упасть до исправления. Отдельно — какие
проверки он запускал и что осталось непроверенным. Процентов готовности нет.

## Навыки

Агент подгружает навыки `security-review`, `code-review`, `vercel-react-best-practices` и
`web-design-guidelines`, для интерфейса — `a11y-audit:a11y-audit`, если он есть. Это навыки
окружения Claude Code (встроенные, пользовательские и плагинов), в репозитории их нет: если на
машине какого-то нет, агент работает без него по своим правилам.

## Порядок работы

1. Изменение готово, локальные проверки зелёные.
2. Агент проверяет изменение; подтверждённые находки исправляются до PR, каждая — с тестом,
   который падает до исправления.
3. PR, CI 4/4 на последнем коммите, «вливай» владельца.

В CI агент не запускается: для этого нужен ключ API в секретах GitHub — решение владельца.
