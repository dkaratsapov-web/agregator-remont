## 1–3. Все маршруты API

Тест читает `apps/api/openapi.json` (его генерирует код, CI сверяет, что файл свежий) и
проверяет каждую операцию, а не список, написанный вручную. На 23.10.2026: 86 операций,
из них 73 закрытых и 14 административных. Результат: 89 из 89 проверок прошли.

Открытые маршруты (без сессии) и почему:

| Маршрут | Почему открыт |
|---|---|
| `GET /health`, `GET /health/ready` | проверка живости для Docker и автодеплоя; без данных |
| `POST /v1/auth/register`, `POST /v1/auth/login` | вход и регистрация; лимит `AUTH_RATE_LIMIT_PER_MIN`, атомарный счётчик неудачных входов |
| `POST /v1/auth/password-reset` | новый пароль по одноразовой ссылке от администратора; токен проверяет API |
| `GET /v1/auth/oauth/providers`, `POST /v1/auth/oauth/{provider}/authorize`, `POST /v1/auth/oauth/{provider}/callback`, `POST /v1/auth/oauth/complete` | вход через банк: state и PKCE; выключен без ключей |
| `GET /v1/jobs`, `GET /v1/jobs/{id}` | каталог заказов; без контактов заказчика (access-matrix) |
| `GET /v1/contractors/{publicId}` | публичный профиль мастера |
| `POST /v1/leads` | заявка на тестирование; закрыта (503), пока нет реквизитов оператора |

В production всё приложение, кроме главной и заявки, дополнительно закрыто паролем
тестировщика в Caddy (`docs/SECURITY.md`, раздел 8).

## 5–6. Сайт: Server Actions и Route Handlers

- Server Actions: 14 файлов с `'use server'`. Тест находит каждое экспортированное действие и
  требует вызова `isTrustedOrigin` — напрямую или через функцию того же файла (`prepare`,
  обёртка формы). Тест сам проверяет, что ловит действие без проверки.
- Route Handlers: 10 файлов. Все POST и DELETE, которые меняют данные, проверяют Origin:
  `/lead`, `/gate/login`, `/account/avatar` (POST, DELETE). Исключение — `/csp-report`: отчёты
  шлёт сам браузер, поэтому Origin не проверяется; тело до 8000 байт, проверяется тип. Остальные
  обработчики — GET только для чтения (фото, сводка уведомлений, проверка пароля тестировщика)
  и два GET ниже.
- Добавлены тесты: `DELETE /account/avatar` (Origin, сессия, вызов API) и
  `GET /account/notifications/summary` (сессия, без кэша, 502 без подробностей).
- GET, которые ставят cookie, — намеренно:
  - `GET /reset/<токен>` переносит токен ссылки в cookie и уводит на `/reset`, чтобы токен не
    остался в адресе. Чужая ссылка может лишь предложить задать пароль чужому аккаунту.
  - `GET /auth/<банк>/callback` — возврат из банка; защищён cookie со state и PKCE.

## 7. Форма заявки без JS (исправлено)

Было: `<form>` без `method` и `action`. С JS форма отправляла JSON, а без JS браузер ушёл бы
GET-запросом на текущую страницу, и имя с телефоном оказались бы в адресной строке, истории
браузера и журналах прокси. На сервере это пока не случалось: форма выключена, пока нет
реквизитов оператора.

Стало: `method="post" action="/lead"`. `/lead` принимает и обычную форму и отвечает переходом
на `/?lead=<код>#apply`; главная показывает результат по коду. Тесты сначала падали (9 из 22),
после исправления проходят.

## 8. Загрузка картинок

Фото профиля (`processAvatar`) и фото к сообщениям и сдаче этапа (`processPhoto`):

- формат определяется по содержимому; PHP, HTML, SVG со скриптом, GIF, пустой и обрезанный
  файл — 400;
- «бомба»: правильный PNG 7100×7100 (50,4 Мп) размером около 50 КБ отклоняется лимитом
  `limitInputPixels`. Проверка мутацией: без лимита тест падает (sharp обработал бы файл);
- EXIF (модель телефона, геолокация) в результат не попадает; результат всегда WebP.

## 9–10. Заголовки и cookie

- Сайт: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` без камеры,
  микрофона и геолокации, CSP с `frame-ancestors 'none'`, `object-src 'none'`,
  `form-action 'self'`, без `X-Powered-By`. HSTS добавляет Caddy.
- API: заголовки helmet, включая HSTS (ответ `/health` проверен локально).
- Cookie сессии, сброса пароля и входа через банк в production: префикс `__Host-`, `HttpOnly`,
  `Secure`, `SameSite=Lax`, путь `/`, без `Domain`.

## Остаточные риски (не исправлены в коде, решение владельца)

1. **CSP в режиме Report-Only.** Нарушения пишутся в `/csp-report`, но не блокируются.
   Перевод в запрет — после наблюдения отчётов на сервере (`docs/SECURITY.md`, раздел 3).
2. **Лимиты запросов в памяти процесса.** Верны для одного экземпляра API (так устроен деплой).
   Перед масштабированием нужен общий storage (Redis).
3. **Два маршрута записи без отдельного лимита записи:** `POST /v1/me/notifications/read` и
   `POST /v1/reports/mine/seen`. Оба вызываются сами при открытии страницы, повтор ничего не
   меняет, действует общий лимит 120 в минуту. Пояснение записано в коде.
4. **Фото профиля загружается только с JS.** Без JS остальной кабинет работает
   (`docs/NO_JS_FORMS.md`).
