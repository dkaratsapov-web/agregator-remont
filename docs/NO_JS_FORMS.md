# Формы без JavaScript и связанные действия

## Что было

Без JavaScript (браузер отправляет форму обычным POST) ошибка в форме на странице заказа
(отклик с неверной ценой, короткий комментарий к этапу, жалоба, решение модератора) не
возвращалась: браузер ждал ответа бесконечно. Хуже того, процесс web после такого запроса
занимал процессор на 95–110 % и переставал отвечать **всем** остальным посетителям, пока его
не перезапустят. Воспроизведено на production-сборке (`next build && next start`), Next.js
16.4.1 и React 19.3.1, 21.10.2026. Любой, кто прошёл вход тестировщика, мог одним запросом
остановить сайт: это отказ в обслуживании.

Успешные действия работали: они отвечают переходом (`redirect`) и страницу не рендерят.

## Причина

Формы получали действие через `action.bind(null, jobId, …)` и передавали его в
`useActionState`. После POST без JS Next.js рендерит страницу заново с `formState`, и
`useActionState` сверяет подпись действия (`$$IS_SIGNATURE_EQUAL`). У связанного действия
аргументы — обещание; пока оно не разрешено, проверка «подвешивает» компонент (бросает
обещание). При повторе рендер снова вызывает `.bind(...)`, создаётся новая ссылка с новым
неразрешённым обещанием — и так без конца (`react-server-dom-turbopack-client`,
`isSignatureEqual`; цикл повторов Fizz `performWork`). Действия без `.bind` проверку проходят
сразу (`bound === null`).

Проверка на изолированных страницах: форма с несвязанным действием — ответ за 134 мс; та же
форма с `.bind` — нет ответа, процессор 95 %; ошибка не зависит от макета сайта и от того,
динамический ли адрес.

## Что сделано

- Ни одно Server Action в интерфейсе не связывается через `.bind`. Параметры (номер заказа,
  этапа, куда вернуться) передаются скрытым полем `args` — `components/ui/form-args.tsx`,
  чтение и проверка типов — `lib/form-args.ts`. Для каждого действия есть обёртка
  `…FormAction(prev, form)`, которая читает `args` и вызывает прежнюю функцию: та по-прежнему
  проверяет каждый аргумент (связанные аргументы тоже приходили от клиента и были недоверенными).
- Тест-ограждение `lib/no-bound-actions.test.ts`: `.bind(null` в коде приложения ломает
  проверки.
- Браузерный `scripts/accounts-e2e.mjs`: без JS ошибка формы отклика и смены пароля приходит
  за секунды, а сервер после этого отвечает на другие запросы.

## Правило

Новая форма с параметрами — `<FormArgs values={[…]} />` и обёртка, а не `.bind`. Обход
`ReportButton` (`js=1` и переход на `?report=…`) остался: он работает и не мешает.
