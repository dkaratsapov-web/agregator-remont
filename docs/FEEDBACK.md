# Поддержка: обращения участников тестирования

Канал связи участников закрытого теста с командой: ошибка, идея или вопрос прямо из кабинета,
ответ администратора там же. Критерий беты 7 («поддержка») в `docs/audit/BETA_RELEASE_MATRIX.md`.
Типы — `packages/shared/src/feedback.ts`, API — `apps/api/src/feedback`, страницы —
`/account/feedback` и `/admin/feedback`.

## Человек

- Ссылка «Написать в поддержку» — в подвале каждой страницы сайта и в меню кабинета
  («Поддержка»). Ссылка из подвала несёт адрес страницы (`?from=/jobs`): он сохраняется в
  обращении, чтобы было понятно, где случилась ошибка. Принимается только путь сайта
  (`/…` без пробелов и служебных символов), полный адрес другого сайта — нет.
- Форма: вид («Ошибка», «Идея», «Вопрос») и текст от 10 до 2000 символов. Работает без JS;
  ошибка показывается рядом с формой, введённый текст не теряется.
- «Мои обращения» — последние 50 своих обращений: вид, текст, страница, «Ждёт ответа» или
  «Есть ответ» с ответом поддержки.
- Не больше 10 обращений за сутки от одного человека (429 `DAILY_QUOTA_EXCEEDED` с
  `Retry-After`). Обращения одного человека идут по очереди (блокировка его строки), поэтому
  параллельные отправки не проходят сверх лимита. Плюс общий лимит записи на адрес.
- Чужих обращений человек не видит: список отдаётся только по своему аккаунту.

## Администратор (`/admin/feedback`, «Обращения» в меню)

- Фильтры «Без ответа» (старые первыми — очередь), «С ответом» и «Все» (новые первыми), по 20
  на странице. В карточке: вид, текст, страница, автор (имя, ID, роль).
- Ответ — один раз, от 2 до 2000 символов. Два администратора, ответившие одновременно, идут
  по очереди: второй получает 409 «На это обращение уже ответили», первый ответ не затирается.
  Ответ пишется в журнал аудита (`FEEDBACK_REPLIED`).
- Автор узнаёт об ответе так же, как о решении по своей жалобе: ответ входит в число на значке
  уведомлений, на странице уведомлений — строка «Поддержка ответила на ваши обращения», в «Моих
  обращениях» — пометка «Новый ответ». Таблицу уведомлений это не трогает (она привязана к
  заказу): сводка `GET /v1/me/notifications/summary` считает поле `feedbackReplies` по
  `feedback.author_seen_at`.
- Ответ просмотрен, когда автор открыл «Мои обращения» (`POST /v1/me/feedback/seen`, без JS —
  кнопкой «Отметить все прочитанными» на странице уведомлений). Повтор ничего не меняет, чужие
  обращения не затрагиваются.

## Данные

- Таблица `feedback` (миграции `20261029100000_feedback` и `20261030100000_feedback_seen` —
  столбец `author_seen_at`, допускает NULL, откат безопасен). База сама держит границы: текст
  10..2000, страница — путь сайта, ответ и время ответа заданы вместе или оба пусты
  (`feedback_*_check`). При удалении пользователя его обращения удаляются (`ON DELETE
  CASCADE`), у ответившего администратора ссылка обнуляется (`SET NULL`).
- Обращения попадают в файл «Свои данные» (раздел `feedback`, с ответами) и стираются при
  удалении аккаунта (`docs/ACCOUNTS.md`). Политика конфиденциальности описывает их в разделе 2
  (версия `2026-10-26`).
- Денег, вложений и переписки в обращении нет: только текст. Фото к ошибке — следующим шагом,
  если тестировщики попросят.

## Проверки

- API: `feedback.e2e-spec.ts` — свои и чужие, проверка ввода (вид, длина, страница, лишние
  поля), суточный лимит, очередь и ответ, 409 на повторный ответ, гонка двух администраторов,
  403/404, выгрузка и удаление аккаунта, ответ в сводке уведомлений до просмотра; контракт всех кодов ответа (`contract.e2e-spec.ts`),
  матрица доступа (`route-matrix.e2e-spec.ts`).
- Web: `account/feedback/actions.test.ts` (проверка ввода, адрес страницы, ошибки API, чужой
  Origin).
- Браузер: `scripts/feedback-e2e.mjs` (с JS и без) — ссылка из подвала с адресом страницы,
  отказ на короткий текст, отправка, «Мои обращения», ответ администратора, ответ у автора с
  пометкой «Новый ответ» и строкой на странице уведомлений, отметка просмотра (с JS — при
  открытии, без JS — кнопкой), чужой человек ничего не видит, нет нарушений CSP. Запускается в CI.
