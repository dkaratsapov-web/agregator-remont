# Производительность (ТЗ #37)

Замеры сделаны локально, в контейнере разработки, на production-сборке (`next build` +
`next start`, API `node dist/main.js`, PostgreSQL 16). Это не замер у реальных пользователей:
сеть, устройства и нагрузка сервера другие. Числа годятся для сравнения «до/после» и для
бюджетов в CI, а не как обещание скорости на проде.

## 1. Каталог: поиск на 100 тыс. заказов (ARCH-2, ARCH-7)

**Данные.** 100 000 заказов: 30 % открытых, 50 вариантов города, названия и описания из словаря
работ (`scripts/perf/catalog-seed.sql`). Запросы такие, как их строит Prisma в
`JobsService.list`: страница (20 строк, сортировка по дате) и подсчёт для пагинации.
Повторить: `scripts/perf/catalog-bench.sh` (медиана из 5 запусков `EXPLAIN ANALYZE`).

**Что сделано.** Миграция `20261019120000_catalog_search_indexes`:

- расширение `pg_trgm` и GIN-индексы по `title`, `description`, `city` (поиск `ILIKE '%…%'`
  и город без учёта регистра);
- частичный индекс открытых заказов `(created_at DESC, id DESC) WHERE status = 'OPEN'`;
- удалён `jobs_category_created_at_idx`: ни один запрос по нему не идёт, каталог ищет по всем
  категориям заказа через GIN `jobs_categories_idx`.

| Запрос | До: время, план | После: время, план |
|---|---|---|
| Поиск частого слова, подсчёт | 237 мс, Seq Scan | 47 мс, Bitmap (title + description trgm) |
| Поиск редкой фразы, страница | 282 мс, Seq Scan | 2,2 мс, Bitmap (trgm) |
| Поиск редкой фразы, подсчёт | 251 мс, Seq Scan | 2,2 мс, Bitmap (trgm) |
| Город, страница | 56 мс, Seq Scan | 16 мс, Bitmap (city trgm) |
| Город, подсчёт | 59 мс, Seq Scan | 15 мс, Bitmap (city trgm) |
| Только открытые, подсчёт | 20 мс, Seq Scan | 4,8 мс, Index Only Scan (частичный) |
| Открытые + город + поиск | 28–32 мс, Parallel Seq Scan | 16–17 мс, Bitmap (city trgm) |
| Категория (без изменений) | 0,2 / 9,6 мс, Index / Bitmap | 0,1 / 9,5 мс, те же индексы |
| Поиск частого слова, страница | 0,5 мс, Index Scan по дате | 0,6 мс, то же |

Ограничения: запрос короче 3 символов (минимум поиска — 2) trigram-индекс почти не сужает;
подсчёт по очень частому слову остаётся десятками миллисекунд (совпадает треть таблицы).
Индексы занимают место и замедляют запись заказа; при текущих объёмах это незаметно.
`CREATE INDEX` без `CONCURRENTLY` блокирует запись в `jobs` на время построения: на
сегодняшнем объёме — доли секунды, на миллионах строк миграцию надо переписать.

## 2. Веб: LCP, CLS, INP

`scripts/ux-e2e.mjs` (в CI) открывает страницы в Chromium и считает показатели через
`PerformanceObserver`. INP — самое долгое взаимодействие (нажатие, ввод), наведение мыши не
учитывается. Бюджеты в CI: LCP < 2,5 с, CLS < 0,1, INP < 200 мс.

| Страница | Экран | LCP | CLS | INP (действие) |
|---|---|---|---|---|
| `/` | 1440×900 | 220–356 мс | 0 | — (прокрутка колесом не взаимодействие) |
| `/` | 390×844, touch | 188–280 мс | 0 | — |
| `/jobs` | 1440×900 | 244–332 мс | 0 | 96–120 мс (нажатие в поле поиска) |
| `/jobs` | 390×844, touch | 204–420 мс | 0 | 40–56 мс |
| `/account/jobs/new` | 1440×900 | 208–252 мс | 0 | 112–120 мс (открыть список категорий) |
| `/account/jobs/new` | 390×844, touch | 168–196 мс | 0 | 40–64 мс |

Диапазоны — разные прогоны на одном коде. Сеть локальная, без задержки, CPU не замедлялся:
на телефоне в мобильной сети LCP будет заметно больше. Для реальных цифр нужен сбор
показателей у посетителей (RUM) после публичного запуска; сейчас его нет.

## 3. Видео пролёта на главной (PR #35)

Проверяется `scripts/ux-e2e.mjs` и `scripts/landing-e2e.mjs`:

- первый кадр — картинка, ролик вперёд грузится после события `load` и не задерживает
  первую отрисовку;
- обратный ролик грузится только после того, как прямой готов к проигрыванию;
- при прокрутке вверх показывается обратный ролик (проверено по стилю видео во время
  прокрутки колесом);
- при `Save-Data` и на медленной сети (2g/3g) обратный ролик не грузится вообще, вверх кадр
  перематывается в прямом ролике;
- при `prefers-reduced-motion` шаги показаны списком (тест); видео не грузится — проверено
  при диагностике аудита, отдельной автоматической проверки нет;
- при уходе со страницы оба ролика останавливаются — по коду (`flight-video.tsx`, снятие
  эффекта), тестом не проверено.

Не проверено: декодирование на слабых телефонах и реальная скорость загрузки по мобильной
сети — нужны устройства.
