# Аналитика без персональных данных

Страница администратора `/admin/analytics` (меню «Аналитика») показывает, сколько раз за день
прошли шаги воронки за 7, 30 или 90 дней. API: `GET /v1/admin/analytics?days=7|30|90`
(только администратор).

## Что считается

| Шаг                                                                          | Откуда число                                                                                        |
| ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Регистрации заказчиков и подрядчиков                                         | `users.created_at` по роли                                                                          |
| Открытия каталога                                                            | счётчик: первая страница каталога (`GET /v1/jobs`), листание не считается                           |
| Просмотры карточек заказов                                                   | счётчик: найденная карточка (`GET /v1/jobs/:id`)                                                    |
| Начатые черновики                                                            | счётчик: создание черновика                                                                         |
| Опубликованные заказы, отклики, выбран исполнитель, отзывы, открыты контакты | журнал действий (`JOB_CREATED`, `BID_CREATED`, `BID_ACCEPTED`, `REVIEW_CREATED`, `CONTACTS_SHARED`) |
| Заказы выполнены                                                             | журнал: `JOB_CLOSED` с исходом «выполнен» (отменённые не считаются)                                 |
| Сообщения в переписке                                                        | `job_messages.created_at`                                                                           |

Дни — по Москве (UTC+3, без перехода на летнее время).

## Что не хранится

- Счётчики (`usage_counters`) — только «день, шаг, число». Нет id людей, IP-адресов, cookie,
  адресов страниц или устройств; в браузере ничего не запускается.
- Ответ API и страница — только числа. Тест `analytics.e2e-spec.ts` проверяет, что в ответе
  нет email, имён и id.
- Поэтому согласие на аналитические cookie не нужно; сведения о самой обработке ПД сервиса —
  в политике (решение владельца и юриста).

## Ограничения

- Открытия каталога, просмотры карточек и начатые черновики считаются с выкладки этой версии;
  остальные шаги берутся из уже записанных данных, поэтому видна и прошлая история.
- Просмотры — это запросы страниц: повторные открытия и поисковые роботы тоже считаются.
  Уникальных посетителей без идентификатора посчитать нельзя — это осознанный выбор.
- Открытия каталога, карточек и начатые черновики копятся в памяти API и пишутся в базу одним
  запросом раз в 30 секунд и при штатной остановке (`UsageCounters` в
  `apps/api/src/analytics/usage.ts`). Публичный GET не превращается в запись в базу на каждый
  запрос, и частые открытия не нагружают одну строку блокировками. Отчёт перед подсчётом
  сбрасывает накопленное, поэтому администратор видит свежие числа своего экземпляра API.
- Цена такого решения: при аварийном падении API теряются числа последних секунд (до 30).
  При штатной остановке делается одна последняя запись; если база в этот момент недоступна,
  числа теряются, а в журнале API остаётся ошибка `counters lost at shutdown: N`.
- При нескольких экземплярах API каждый пишет свою часть, суммы складываются в базе. Отчёт
  сбрасывает только свой экземпляр: числа остальных попадают в него с задержкой до 30 секунд.
- Ошибка записи не ломает действие человека: пишется предупреждение в журнал приложения,
  несохранённое возвращается в очередь и уходит при следующем сбросе.
- Числа за период — не когорты: «выполнено» за неделю может относиться к заказам,
  опубликованным раньше.
