## 2. Покрытие кода

Замер `test:cov`, тот же запуск, что в CI. Пороги в CI немного ниже замера, чтобы покрытие
не падало незаметно.

| | Операторы | Ветвления | Функции | Строки | Порог CI (о/в/ф/с) |
|---|---|---|---|---|---|
| API (`src/**`, все файлы) | 95,5 % | 85,9 % | 96,8 % | 96,8 % | 95 / 85 / 96 / 96 |
| Web (`src/**/*.ts`, без компонентов) | 71,6 % | 72,3 % | 74,0 % | 73,1 % | 67 / 68 / 70 / 69 |

До аудита: API 96,6 / 86,4 / 97,5 / 98,0 % — без файлов, которые ни один тест не загружал
(TEST-9: теперь `collectCoverageFrom` учитывает все); покрытие web не измерялось (TEST-8).

Покрытие web считается по модулям с логикой (`lib/`, Server Actions, Route Handlers).
Компоненты React (`.tsx`) проверяют браузерные сценарии: построчное покрытие для них не
собирается. Без unit-тестов остаются: `lib/api.ts` наполовину (часть функций проверяют
действия и интеграция), вход через банк (выключен, отложен), `manifest.ts`, `robots.ts`,
хуки главной (`use-flight-snap.ts` — проверяется в `landing-e2e`/`ux-e2e`).

API e2e с чтением базы (#40 п. 7): `my-jobs-concurrency.e2e-spec.ts` (6 параллельных правок с
одной версией — одна 200, пять 409, в базе победитель, одна запись журнала; пометка только у
ожидающих откликов), `drafts.e2e-spec.ts` (то же для черновика, удалённый — 404),
`my-jobs.e2e-spec.ts` (ключ публикации с другим содержимым — 409).

влияли): API 383/383 и web 316/316 в каждом прогоне. Нестабильных тестов, `.skip` и

## 5. Что не проверено

- Реальные устройства и браузеры: Chromium и WebKit (эмуляция iPhone) в CI; Firefox,
  настоящие iOS и Android — нет.
- Нагрузка: параллельность проверена гонками в e2e, нагрузочного теста нет.
- Вход через Сбер ID и Т-Банк ID с настоящими банками (отложено, выключено).
- Копия, восстановление и откат на настоящих Docker и Postgres проверяются учениями в CI
  (`scripts/drills.sh`) на одноразовом стеке раннера. На VPS с реальным объёмом, хранилищем
  владельца и systemd — после настройки владельцем, см. `DEPLOY_READINESS.md`.
