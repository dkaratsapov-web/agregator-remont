# Аккаунты и доверие (фаза 2)

Сброс пароля без почты, пользователи для администратора, отзывы и карточка мастера, избранное,
«Переписки», «Мои жалобы», автопроверка контактов. Типы — `packages/shared/src/auth.ts`,
`reviews.ts`, `moderation.ts`, `jobs.ts`; миграция `20261024100000_accounts_reviews`.

## Новый пароль по ссылке

Почты у сервиса пока нет, поэтому ссылку выдаёт человек:

- **Администратор:** `/admin/users` → найти по email, имени или ID → «Ссылка для нового пароля»
  → «Создать ссылку» → скопировать и передать владельцу аккаунта (мессенджер, звонок).
- **Команда на сервере** (например, администратор сам не может войти). На VPS из
  `/opt/agregator`, меняет только таблицу ссылок:

  ```bash
  docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.proxy.yml \
    run --rm --no-deps api node dist/cli/password-reset-link.js user@example.ru https://домен
  ```

Правила: ссылка действует 24 часа и один раз; новая ссылка отменяет прежние; в базе только
SHA-256 токена; заблокированному ссылку не выдать и пароль по ней не сменить. Ссылка
`/reset/<токен>` сразу переносит токен в cookie (HttpOnly, 30 минут) и уводит на `/reset`:
токена нет в адресной строке и истории. После смены пароля все прежние входы завершаются, человек
сразу входит с новым паролем. На странице входа — «Забыли пароль?» с этим порядком.

API: `POST /v1/admin/users/:id/password-reset` (администратор, 201 `{ token, expiresAt }`),
`POST /v1/auth/password-reset` `{ token, password }` (лимит входа, 200 — новый сеанс; 400 —
ссылка недействительна; 403 — аккаунт заблокирован). Две одновременные отправки одной ссылки —
пароль меняется один раз (блокировка строки ссылки).

## Пользователи для администратора

`/admin/users`: поиск по части email, имени или номеру аккаунта; у каждого — роль, дата, число
заказов и откликов, открытых жалоб на его заказы, сообщения и отклики; блокировка и ссылка для
пароля. `GET /v1/admin/users?q=&page=`.

## Отзывы и карточка мастера

- Отзыв оставляет заказчик, когда закрыл заказ **как выполненный** с выбранным исполнителем:
  оценка 1–5 и текст до 1000 символов, один на заказ, изменить нельзя (повтор — 409; две
  одновременные отправки — сохраняется одна).
- Рейтинг — среднее по видимым отзывам с одним знаком; скрытый модератором отзыв
  (`POST /v1/admin/reviews/:id/hidden`) не показывается и не считается.
- Карточка `/contractors/<ID>`: имя, профиль, рейтинг, число выполненных заказов, отзывы
  (по 10, страницами); без email и телефона. Заказчик видит рейтинг и ссылку на карточку в
  каждом отклике, мастер — ссылку «Как видят заказчики» в своём профиле.
- Уведомления об отзыве нет: новые виды уведомлений не добавлялись, прежний API не прочитал бы
  неизвестное значение enum при откате (проверено на Prisma 6).

## Избранное и «Переписки»

- «В избранное» на странице заказа (работает без JS), список — `/account/favorites`, до 200
  заказов; скрытые модератором заказы из списка пропадают.
- `/account/chats`: сделки с выбранным исполнителем (в работе и закрытые), отметка «Новое»,
  переход к переписке. Берутся последние 50 заказов или откликов (предел страницы API).

## «Мои жалобы» и автопроверка

- `/account/reports`: свои жалобы, статус и решение администратора. Непросмотренные решения
  входят в число на колокольчике и отмечаются просмотренными при открытии страницы или кнопкой
  «Отметить все прочитанными».
- Автопроверка: в сообщении или отклике похоже на контакты (телефон, почта, ссылка, мессенджер,
  `@имя`) — автор видит подсказку при вводе, текст отправляется, администратор видит пометку во
  вкладке «Автопроверка» очереди жалоб и решает (скрыть, заблокировать, «нарушения нет»).
  Правила распознавания и примеры без ложных срабатываний (цены, площади, даты) —
  `apps/api/src/moderation/content-flags.spec.ts`.
